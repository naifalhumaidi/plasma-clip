# Development

Architecture, build and test notes for `custom-clipboard`.

## Layout

```
src/main.cpp      the entire application (~1400 lines)
build.sh          compile + dependency check
install.sh        user-level install
uninstall.sh      removal + Klipper restore
README.md         user guide
DEVELOPMENT.md    this file
AGENTS.md         rules for AI agents
docs/             screenshots, generated by --preview
```

Single translation unit by design: there is no build system to learn and no
dependency beyond Qt6 + KGlobalAccel.

## Building

```bash
./build.sh
```

Produces `./custom-clipboard`. The script checks for all four dependencies and
names anything missing rather than failing with a compiler error.

Under the hood:

```bash
g++ -std=c++17 -O2 -fPIC src/main.cpp -o custom-clipboard \
    $(pkg-config --cflags --libs Qt6Widgets Qt6DBus Qt6Sql) \
    -I/usr/include/KF6/KGlobalAccel -lKF6GlobalAccel
```

There is no `moc` step: no class declares Qt signals/slots, only lambdas and
function-pointer connections.

## Running modes

| Command | Purpose |
|---|---|
| `./custom-clipboard` | normal, resident, waits for Meta+V |
| `./custom-clipboard --selftest` | one-line summary, no window |
| `./custom-clipboard --test` | full suite, no window |
| `./custom-clipboard --preview DIR` | render the UI states to PNG |
| `./custom-clipboard --screenshot F --state S` | render one state |

`--preview` / `--screenshot` need `QT_QPA_PLATFORM=offscreen` to avoid touching
the real desktop:

```bash
QT_QPA_PLATFORM=offscreen ./custom-clipboard --preview /tmp/states
QT_QPA_PLATFORM=offscreen ./custom-clipboard --screenshot out.png --state hover
```

States: `all`, `starred`, `notstarred`, `search`, `alpha`, `trash`, `new`,
`hover`, `edit`, `confirm`. The tab states need a fixture with content in that
tab — `docs/make-screenshots.sh` builds one.

## Testing

```bash
QT_QPA_PLATFORM=offscreen ./custom-clipboard --test
```

Checks over the read path, sorting, search and tab filtering, the write path,
the trash, the confirm popup, outside-click dismissal, double-click handling and
the environment. The suite prints its own total, so do not quote a number here.

Principles the suite follows:

- **Write tests never touch your history.** `CUSTOM_CLIPBOARD_DATA` redirects the
  data directory for the *entire* suite, not just the write-path block. This was
  once scoped too narrowly and every later check ran against the real database —
  see [AGENTS.md](AGENTS.md). The suite refuses to start if the sandbox is not
  active, asserts the real row count is unchanged at the end, and fails loudly
  if the real history is empty.
- **The trash sidecar is sandboxed too.** `CUSTOM_CLIPBOARD_TRASH` points the
  trash at the sandbox for the whole suite, with its own refuse-to-start guard —
  an unsandboxed trash test would empty the real trash for the same reason an
  unsandboxed delete test destroyed the real history.
- **Synthetic events, not injected input.** Clicks are delivered with
  `QApplication::sendEvent` straight to the widget. That exercises the same
  hit-testing a real click does without sending anything to the OS input layer.
  See [AGENTS.md](AGENTS.md) for why that matters.
- **Synthetic events must match what the OS really sends.** Two plain
  `MouseButtonPress` events are *not* a double-click; the real one arrives with
  a `MouseButtonDblClick` second press. Synthesising the wrong sequence hid a
  paste bug for two rounds of guessing.
- **Fixtures, not live data.** Ordering tests use a fixed synthetic
  `QVector<Entry>`. An earlier version asserted against the user's real history
  and failed the moment every entry happened to be starred.
- **Test the code path the UI uses.** The star bug survived because the test
  hand-wrote its own `UPDATE` while the app's setter was the broken one.
- **A new test must be shown to fail.** Revert the fix and watch it go red, or
  it is not evidence of anything.
- **Row-body clicks are asserted not to** star or delete, but are never actually
  triggered, because that path ends in a ydotool injection. The paste path is
  asserted with a counter on `choose()` rather than by letting it run.

## Architecture

```
Entry            one history row
readHistory()    SELECT from history3.sqlite          (read-only)
loadImage()      resolve an image blob to a QImage
imageFileName()  Klipper's stored filename for an image
Store            shared state: entries, trash, thumbnail cache, hover row
RowDelegate      paints a row: thumbnail, text, timestamp, buttons
Deck             the popup: layout, four tabs, search, sort, actions
loadTrash()      read the trash sidecar (~/.local/share/custom-clipboard/trash.json)
trashEntry()     capture a row into the trash, then drop it from history
restoreEntry()   copy a trashed row back into history
```

`Store` exists so `RowDelegate` never needs to know about `Deck` — depending on
it directly is a circular dependency and will not compile.

Both the UI and the test suite call the same `sortEntries()` and `filterRows()`
free functions, so tests cannot drift from behaviour.

### Button geometry

`starButtonRect()` and `removeButtonRect()` are the single source of truth, used
by both painting and hit-testing, so the two can never disagree. `remove` is
outermost (10px from the row edge); `star` sits 4px inboard of it.

The delegate's `sizeHint` returns **no width** on purpose. Returning a fixed
width makes item rects wider than the viewport, which decouples where rows are
painted from where clicks are measured — that bug cost real debugging time.

Hit-testing must also accept `MouseButtonDblClick` as well as
`MouseButtonPress`. Qt sends the second press of a double-click as a DblClick
event; a filter that watches only Press lets it fall through to the list, which
then emits `itemClicked` and pastes.

### Closing on an outside click

The panel is a `Qt::Tool` window, deliberately **not** `Qt::Popup`. A popup
needs a live transient parent, and anchoring one to the focused window made the
panel fail to appear at all — do not retry that without a way to test it.

Wayland gives a Tool window no pointer grab, so there is no "clicked outside"
event to receive. The panel infers it from `WindowDeactivate`, which is
ambiguous: the panel's own widgets deactivate it too. `handleDeactivate()`
therefore only dismisses when the pointer is off the panel and no popup of ours
owns the interaction, and it is the single place that rule lives.

### Pasting

`choose()` copies the entry through Klipper's D-Bus API, hides the panel, waits
`pasteDelayMs`, then has `ydotool` press Ctrl+V into whatever now has focus.

The daemon is probed before that, not assumed — see `ydotoolReady()`.

## Click tracing

For diagnosing a mis-click with real numbers instead of guesswork:

```bash
CUSTOM_CLIPBOARD_DEBUG=1 ~/.local/bin/custom-clipboard
```

Appends to `/tmp/custom-clipboard-clicks.log`:

```
GEOMETRY viewportW=362 row=(0,88 362x44) star=(291,95 28x28) remove=(323,95 28x28)
STAR row=2 pos=341,118
```

This is how the button-position bug was actually found: the log showed clicks
landing at x=341 while the hit rect started at x=341, i.e. exactly on the edge.

## Releasing

1. `./build.sh && QT_QPA_PLATFORM=offscreen ./custom-clipboard --test`
2. Regenerate screenshots: `./custom-clipboard --preview docs/` then copy `all.png` to `docs/preview.png`
3. Bump `QCoreApplication::setApplicationVersion`
4. Commit — the compiled binary is gitignored, never commit it
